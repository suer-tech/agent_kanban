Этот пакет устанавливает обмен с https://ocr-agent-kanban.vercel.app. Ключей доступа в пакете нет. Для работы нужны установленный Codex Desktop либо VS Code с официальным расширением Codex и личный `connection.json` от администратора сервиса. Конфигурация содержит `url`, `token` только своего участника и, если задан, стабильный `bridgeId`. Не используй административные credentials, SSH-ключ или ключ другого разработчика.

Сам запроси у пользователя путь к выданному файлу ключа нужной роли (`requester.connection.json`, `executor.connection.json` или `connection.json`), если путь ещё не указан. Проси путь, не токен в чате. Не требуй переносить файл вручную: передай установщику его исходное расположение, установщик создаст служебные папки и сохранит рабочий ключ в локальном `client.json`. Сам проверь результат без вывода секрета. Исходный файл не удаляй. Папку проекта и клиент `vscode`, `desktop` либо `auto` с предпочтением уточни только при отсутствии достоверных данных. Заказчик работает в своей папке проекта; исполнитель — в локальной копии `https://github.com/suer-tech/OCR_document_reader` на ветке. Установщик определяет роль по ключу на сервере.

Запусти скрипт из каталога этого навыка:

- Windows: `powershell.exe -NoProfile -File scripts/setup.ps1 -Connection ПУТЬ -Project ПАПКА -Transport vscode`.
- macOS: `/bin/bash scripts/setup.sh --connection ПУТЬ --project ПАПКА --transport vscode`.

Передавай пути отдельными аргументами с корректным экранированием оболочки. Для `auto` передай также `-Preferred desktop` на Windows или `--preferred desktop` на macOS. Без аргументов установщик задаст эти вопросы сам. Скрипты загружают отдельный Node.js 24 с nodejs.org и проверяют встроенный SHA256; системные Node.js и PATH не меняются. Устанавливаются рабочий навык, мост, помощник (если выбран VS Code), запуск после входа пользователя и подписанные обновления адаптера. Сетевые и файловые разрешения текущего Codex действуют отдельно: не обходи блокировку и не обещай установку до фактического результата.

По умолчанию установка находится в `%LOCALAPPDATA%/OCR Kanban` или `~/Library/Application Support/OCR Kanban`. В проекте создаются `.ocr-kanban.json` и `.ocr-kanban-data`; Git исключения добавляются локально. Старый навык с тем же именем и чужая проектная конфигурация автоматически не перезаписываются. При таком конфликте сохрани настройки и предложи явную миграцию.

После установки прочитай `status.json`, `update-status.json` и `compatibility.json` из папки установки. Не выводи `client.json`, содержимое `.runtime/ide.json`, bearer-токены и переписку. `installed_pending_client_check` не означает доставку. `waiting_for_client` — открой нужный клиент; `waiting_for_adapter` — версия ещё не имеет проверенного адаптера, события остаются на сервере. Обычная установка навыка не даёт права отвечать на согласования или запускать реальные задачи вместо разработчика.

**macOS:** скрипты установки и платформенный порт подготовлены для Apple Silicon и Intel, но в этой поставке нет подтверждённого живым тестом macOS-профиля IPC. Не объявляй macOS полностью поддерживаемой. После запуска на реальном Mac выполни `scripts/diagnose.mjs` через Node из `runtime/`, сохрани обезличенный отчёт и проверь новую задачу, возврат в исходный чат, вопрос разработчику и доставку после перезапуска. Публикация проверенного профиля выполняется сопровождающим; установщик не утверждает новый профиль сам.

Обновления: служба периодически замечает изменение приложения, повторно обнаруживает его путь и проверяет точные отпечатки. Новый выпуск принимается только с подписью издателя и возрастающим номером, сначала проходит проверку совместимости; при несовместимости старые операции не отправляются заново вслепую. Отсутствующий адаптер нельзя исправлять отключением проверки или автоматическим утверждением нового хеша.

Удаление автозапуска: запусти `installer/uninstall.mjs` из текущего установленного выпуска через приватный Node с аргументом пути установки. Он останавливает службу и отключает только её автозапуск; данные и ключи сохраняются для явного решения владельца.
