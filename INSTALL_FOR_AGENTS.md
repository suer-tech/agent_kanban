# Инструкция установки для агента

Цель — самостоятельно подготовить компьютер разработчика к обмену задачами OCR через существующий сервис. Пользователь даёт ссылку на репозиторий, файл ключа и при необходимости папку проекта/клиент. Ниже описана установка клиента; сервер разворачивать не нужно.

## 1. Сохрани контекст и получи установщик

Запомни абсолютный путь исходной рабочей папки пользователя. Клонируй `https://github.com/suer-tech/agent_kanban.git` в отдельный каталог установки, не внутрь исходников его проекта. Не меняй remote существующего проекта и не пересоздавай существующий checkout. Если Git отсутствует, скачай ZIP репозитория средствами своей среды; не выполняй удалённый код через `curl | sh`.

Прочитай `AGENTS.md`, этот файл и `skills/ocr-kanban-setup/SKILL.md`. Установочный навык уже готов: для запуска из клона не требуется предварительно копировать его в пользовательскую папку навыков.

## 2. Определи параметры

1. **Файл доступа — запроси путь сам.** Если пользователь ещё не передал его, спроси: «Где лежит выданный файл ключа вашей роли — заказчика или исполнителя OCR? Укажите полный путь к файлу». Не проси вставлять токен в чат и не требуй положить файл в специальную папку. Он может остаться в «Загрузках» или другом доступном месте. Сам передай этот путь установщику: он создаст нужные папки и сохранит рабочие настройки в `%LOCALAPPDATA%/OCR Kanban/client.json` или `~/Library/Application Support/OCR Kanban/client.json`. Сам проверь наличие настроек, не выводя их секретное содержимое. Исходный файл не удаляй. Если файла ещё нет, поясни, что администратор канбана должен выдать ключ нужной роли; публичная ссылка сама по себе не выдаёт доступ. Не ищи и не выбирай чужие ключи автоматически.
2. **Проект.** Используй исходную рабочую папку, если пользователь не указал другую. Если исходной папкой был сам установщик либо роль исполнителя не соответствует OCR-репозиторию, уточни путь. Не клонируй OCR поверх чужих изменений. Для исполнителя нужна чистая локальная копия `suer-tech/OCR_document_reader` на ветке; мост проверяет GitHub перед задачей.
3. **Клиент.** Используй известный источник текущего чата — VS Code или Codex Desktop. Если источник не установлен достоверно, уточни `vscode` / `desktop`; `auto` выбирай только при намерении использовать оба клиента и известном предпочтении. Не меняй клиент существующей задачи молча.
4. **Платформа.** На Windows x64 есть живые проверки. На macOS, включая M5, и Windows ARM64 подготовка есть, но подтверждённых адаптеров пока нет. Сообщи это до запуска, не объявляй такой компьютер готовым к обмену.

Нужны установленный выбранный клиент и вход разработчика в его аккаунт. Если требуется вход в Codex, оставь его владельцу аккаунта; не запрашивай пароль OpenAI и не используй ключ канбана для авторизации в OpenAI. Готовый VSIX устанавливает зависимость официального Codex через штатный CLI VS Code, если она отсутствует. Сам VS Code или Codex Desktop пользователь устанавливает из официального источника.

Файл доступа имеет вид:

```json
{
  "url": "https://ocr-agent-kanban.vercel.app",
  "token": "<ключ своей роли, выданный администратором>"
}
```

Название файла не задаёт роль. Установщик проверяет `/api/me` и допускает только `document-agent` (заказчик) или `ocr-agent` (исполнитель). В текущей версии это ключи двух ролей, а не индивидуальные учётные записи разработчиков. Административные ключи использовать нельзя.

## 3. Запусти установку с полными аргументами

Windows PowerShell, в рабочем каталоге клона:

```powershell
.\install.ps1 -Connection "C:\Users\Developer\.codex\ocr-kanban\requester.connection.json" -Project "C:\Projects\document-app" -Transport vscode
```

Вызов из другой оболочки: `powershell.exe -NoProfile -File <абсолютный путь install.ps1>` с теми же аргументами. Пути передавай отдельными аргументами с корректным экранированием; не подставляй токен в командную строку.

macOS, предварительный порт:

```bash
/bin/bash ./install.sh --connection "$HOME/.codex/ocr-kanban/requester.connection.json" --project "$HOME/Projects/document-app" --transport vscode
```

Исполнитель в Codex Desktop использует свой `executor.connection.json`, папку OCR и `desktop`. Для обоих клиентов укажи `auto` и `-Preferred desktop` / `--preferred desktop` либо `vscode`.

Загрузчики используют Node.js 24.22.0, автоматически выбирают архитектуру, скачивают архив с nodejs.org и проверяют встроенный SHA256. Системные Node.js/PATH не меняются, npm-зависимости не нужны. Подпись клиента проверяется публичным Ed25519-ключом поставки. Не запускай пересборку и не создавай новую пару ключей издателя ради установки.

Не заверши работу после выдачи команды: дождись её результата и продолжи диагностику. Если политика среды не разрешает конкретную операцию, укажи эту операцию и причину; не отключай защиту и не утверждай, что установка завершена.

## 4. Проверь установленное состояние

Корень установки:

- Windows: `%LOCALAPPDATA%\OCR Kanban`.
- macOS: `~/Library/Application Support/OCR Kanban`.

Прочитай **без публикации токенов** `installation.json`, `current.json`, `status.json` и, если существует, `update-status.json`. `client.json` содержит секрет. `.runtime/ide.json` содержит локальный секрет помощника — не печатай его. Открой выбранный клиент, если он закрыт. Новое расширение VS Code может потребовать перезагрузки окна. Не закрывай активную работу пользователя принудительно.

Состояния:

| Состояние | Что означает и что сделать |
|---|---|
| `installed_pending_client_check` | Файлы установлены, соединение ещё не подтверждено |
| `starting` | Мост запускается; дождись следующей проверки |
| `running` | Worker подтвердил запуск; дополнительно проверь диагностику |
| `waiting_for_client` | Нужный клиент/помощник недоступен; открой его, проверь вход и активацию помощника |
| `waiting_for_adapter` | Для этой платформы/версии нет подтверждённого адаптера; очередь сохраняется, требуется выпуск сопровождающего |
| `stopped` | Служба остановлена |

Проверка без отправки сообщения и без запуска модельного хода:

Windows PowerShell:

```powershell
& "$env:LOCALAPPDATA\OCR Kanban\runtime\node.exe" ".\skills\ocr-kanban-setup\scripts\diagnose.mjs"
```

macOS:

```bash
"$HOME/Library/Application Support/OCR Kanban/runtime/node" ./skills/ocr-kanban-setup/scripts/diagnose.mjs
```

Она сохраняет `compatibility.json`: отпечаток адаптера, доступность приватного IPC, initialize, чтение истории и обнаружение рабочего навыка. `readyForLiveTest:true` означает готовность к следующему тесту, не проверенную доставку. `liveDeliveryVerified:false` нельзя пересказывать как успешно выполненный обмен. На Mac без профиля будет ожидание адаптера — не исправляй это изменением хешей.

Проверь рабочий навык в `~/.agents/skills/ocr-kanban`, проектную ссылку `.ocr-kanban.json`, локальную папку `.ocr-kanban-data` и пользовательский автозапуск. Установщик добавляет локальные Git-исключения; исходники проекта и общий `.gitignore` менять не нужно. Вопросы согласования и журнал доставок не сбрасывай.

## 5. Сообщи разработчику факты

Кратко укажи выбранную роль, проект, клиент, фактический статус и результаты диагностики. При успехе предложи в обычном чате сформулировать первую задачу; не создавай её сам без поручения. Агент применяет рабочий навык `ocr-kanban`, а установочный скилл повторно вызывать для каждой задачи не требуется.

Автозапуск работает **после входа пользователя**, не до входа и не при выключенном компьютере. В выключенном состоянии сервер хранит сообщения; доставка продолжается после возвращения моста. Адаптеры обновляются из подписанных выпусков автоматически. Новый несовместимый протокол требует работы сопровождающего, а не автоматического переписывания адаптера.

## Уже установленный клиент и удаление

Сначала проверь существующую установку. Не ставь параллельно второй мост, не меняй роль и не перезаписывай старый немаркированный навык. Установщик останавливается при конфликте с legacy-навыком или чужой привязкой проекта; сохрани их и опиши требуемую миграцию.

Чтобы по поручению пользователя отключить автозапуск, Node из `runtime/` запускает `installer/uninstall.mjs` внутри каталога текущего выпуска (`current.json.path`) с аргументом корня установки. Служба останавливается через файловый сигнал; ключи и история остаются. Удалять их нужно только по отдельному запросу владельца.
