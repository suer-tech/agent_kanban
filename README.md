# Agent Kanban — установка обмена задачами OCR

Установщик соединяет агента заказчика и агента исполнителя OCR через [общую доску](https://ocr-agent-kanban.vercel.app). Заказчик продолжает общение в исходном чате; новая задача создаёт отдельный чат исполнителю. Уточнения идут между агентами, разработчику приходят согласованный план или вопрос с вариантами. Пока компьютер выключен, сообщения сохраняются на сервере.

## Дайте эту ссылку своему агенту

```text
Установи обмен задачами OCR из https://github.com/suer-tech/agent_kanban.
Прочитай AGENTS.md и INSTALL_FOR_AGENTS.md и выполни установку сам.
Сам запроси у меня путь к файлу ключа нужной роли и положи настройки куда требуется.
```

Можно начать только со ссылки и просьбы установить: агент сам запросит путь к файлу ключа нужной роли, а также уточнит проект и клиент, если они неизвестны. Самостоятельно переносить ключ, создавать служебные папки, копировать навык или ставить Node.js не нужно. Агент клонирует репозиторий, запускает установку и проверяет результат.

Установка включает рабочий навык `ocr-kanban`, фоновый мост, помощник VS Code (если выбран этот клиент), отдельный Node.js и запуск после входа пользователя в систему. Системные Node.js и PATH не меняются. Новые подписанные адаптеры загружаются автоматически; если обновление Codex изменило протокол и совместимого адаптера ещё нет, доставка ждёт его выпуска.

## Что потребуется

- Codex Desktop либо VS Code с официальным расширением Codex. Разработчик входит в свой аккаунт самостоятельно.
- Папка проекта. Исполнителю OCR нужна локальная копия `https://github.com/suer-tech/OCR_document_reader` на ветке. Перед обработкой задачи мост проверяет репозиторий и актуальность чистого checkout.
- Файл подключения с ключом **своей роли**, выданный администратором канбана. Заказчику — `requester.connection.json`, исполнителю — `executor.connection.json`. Это доступ к нашему канбану, а не ключ OpenAI.

Оставьте выданный файл там, где он уже находится, например в «Загрузках». Агент сам спросит его путь, передаст его установщику и проверит сохранение ключа в `%LOCALAPPDATA%/OCR Kanban/client.json` или `~/Library/Application Support/OCR Kanban/client.json`. Переносить файл вручную не требуется; исходный файл не удаляется. Публиковать ключ, добавлять его в Git или передавать сам токен через аргументы командной строки не нужно. [connection.example.json](connection.example.json) показывает только формат и не даёт доступа.

## Поддерживаемые платформы

| Платформа | Статус |
|---|---|
| Windows x64 | Проверены bootstrap Node.js, установка помощника VS Code, механизм автозапуска, IPC и чтение истории |
| Windows ARM64 | Есть загрузчик Node.js; живой тест и подтверждённый адаптер отсутствуют |
| macOS Apple Silicon, включая M5 | Подготовлены установщик, LaunchAgent и платформенный порт; полного живого теста и подтверждённого профиля адаптера **пока нет** |
| macOS Intel | Подготовлен загрузчик; полного живого теста и подтверждённого профиля адаптера **пока нет** |

На неподтверждённой платформе установка файлов не означает работающий обмен: служба ожидает проверенный адаптер. Не считайте macOS готовой к рабочей эксплуатации до проверки на реальном Mac. Адаптер использует внутренний IPC Codex; обновление приложения может временно остановить доставку.

## Если устанавливаете вручную

Windows PowerShell, из каталога репозитория:

```powershell
.\install.ps1 -Connection "$env:USERPROFILE\.codex\ocr-kanban\requester.connection.json" -Project "C:\Projects\document-app" -Transport vscode
```

macOS — предварительная версия:

```bash
/bin/bash ./install.sh --connection "$HOME/.codex/ocr-kanban/requester.connection.json" --project "$HOME/Projects/document-app" --transport vscode
```

Для Codex Desktop выберите `desktop`. Для обоих клиентов — `auto` и `-Preferred desktop` / `--preferred desktop`. Если скрипт блокируется политиками организации или средой агента, он должен сообщить точную причину и сохранить прогресс, а не отключать защиту.

## Проверка и обслуживание

Полная инструкция для агента: [INSTALL_FOR_AGENTS.md](INSTALL_FOR_AGENTS.md). Установочный навык: [skills/ocr-kanban-setup/SKILL.md](skills/ocr-kanban-setup/SKILL.md). Готовый архив: [dist/ocr-kanban-setup.zip](dist/ocr-kanban-setup.zip).

Корень установки — `%LOCALAPPDATA%/OCR Kanban` или `~/Library/Application Support/OCR Kanban`. Состояние службы находится в `status.json`; журнал обновлений — в `update-status.json`. Запуск после входа пользователя настраивается через Windows Startup или пользовательский macOS LaunchAgent, без системной службы и root. Поддерживается одна установка и одна роль на компьютере; существующая чужая привязка проекта не перезаписывается автоматически.

В этом репозитории лежит поставка установочного навыка, готовый подписанный клиент и минимальные обёртки запуска. `skills/ocr-kanban-setup/assets/client-release.json` содержит подписанные исходники клиента; их не нужно пересобирать, декодировать вручную или менять для установки. ZIP и распакованный навык относятся к одному выпуску. Закрытый ключ издателя, серверная часть, данные доски и конфигурации участников сюда не входят.

Проверка поставки при установленном Node.js 24: `node --test test/distribution.test.mjs`. Установка не требует npm-зависимостей. Данные об отпечатках и проверках: [RELEASE.json](RELEASE.json), [SHA256SUMS](SHA256SUMS).
